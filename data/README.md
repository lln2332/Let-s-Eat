# 美食数据文档

`restaurants.json` 是程序实际读取、写入的美食名单。内置 46 家店；页面新增的私藏也会保存到这个文件，停止或重启服务不会丢失。

`sources.json` 保存内置店铺的公开资料来源。店铺中的 `source` 是这个数组的下标；`-1` 表示自行添加的私藏。

## 记录格式

```json
{
  "schemaVersion": 1,
  "restaurants": [
    {
      "id": "c-my-lunch-shop",
      "name": "楼下烧腊饭",
      "type": "米饭简餐",
      "low": 20,
      "high": 35,
      "zone": "其他周边",
      "source": -1,
      "note": "想简单吃一顿的时候就来这里。",
      "emoji": "🍚"
    }
  ]
}
```

- `id`：唯一编号，只使用英文字母、数字、下划线和连字符。修改已有店铺时保留原 ID，以便用餐足迹继续关联。
- `name`：店名。
- `type`：分类。推荐使用米饭简餐、面粉馄饨、粤菜茶餐、地方家常、西式日韩、火锅煲类、素食自助、海鲜料理、东南亚菜、私藏好店。
- `low`、`high`：每人估算预算，必须为正数，且 `high >= low`。
- `zone`：商圈。界面内置卓悦 INTOWN、万象前海、前海嘉里中心、恒裕前海、其他周边。
- `source`：内置资料来源编号；自行添加填写 `-1`。页面只允许删除私藏，内置店铺可直接在本文件中维护。
- `note`、`emoji`：推荐语和展示图标。

## 维护方式

可以在页面里添加、删除私藏，也可以直接编辑 `restaurants.json`。手工编辑前先停止服务，修改后再启动，避免手工修改与页面保存同时发生。修改后刷新页面即可加载新名单。

程序会校验字段与 ID，不会用空名单覆盖格式有误的数据文件。每次页面保存都先写临时文件，再替换正式文件，并按顺序处理并发写入。

备份时保存 `restaurants.json` 和 `sources.json` 即可。建议修改内置名单后通过 Git 提交版本，方便追溯。
